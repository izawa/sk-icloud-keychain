# handoff: Mac 間の作業依頼箱

このディレクトリは Dropbox で同期されます。開発用 Mac（Mac mini）の Claude Code セッションが、
別の Mac（MacBook Pro など）の Claude Code セッションに作業を頼み、結果を受け取るために使います。
依頼と結果のファイルは git にはコミットしません（`.gitignore` 済み。この README だけを管理します）。

## ファイル

| ファイル | 書く側 | 中身 |
|---|---|---|
| `NNN-<slug>.request.md` | 依頼する側 | 宛先の Mac、目的、実行してほしい手順、結果に書いてほしいこと |
| `NNN-<slug>.result.md`  | 実行する側 | 実行したコマンドとその出力、判断したこと、最後に状態行 |

`NNN` は 001 から順に増やします。依頼ファイルは書き換えず、追加の依頼は新しい番号で出します。

## 実行する側（例：MacBook Pro の Claude Code）への指示

ユーザーから「handoff の依頼を処理して」と言われたら：

1. このディレクトリで、宛先が自分の Mac で、対応する `.result.md` がまだない `.request.md` を番号順に探す。
2. 依頼の手順を実行する。依頼に書かれていない、取り消せない操作（Keychain の鍵の削除、`~/.ssh` の変更、
   `sudo`、push など）はしない。必要そうなら実行せずに結果にそう書くか、ユーザーに確認する。
3. 結果を `.result.md` に書く。コマンドの出力は省略せずにコードブロックで貼る（長い場合は要点と末尾）。
4. 最後の行に、次のどちらかを書く。依頼する側はこの行を見て結果の完成を判断する。
   - `STATUS: done`
   - `STATUS: blocked — <理由>`

結果ファイルは、書き終えてから最後に `STATUS:` 行を書く（途中の状態を読まれないように）。

## 依頼する側への指示

- 依頼には、宛先の Mac、目的、コマンド、期待する出力、結果に含めてほしいものを書く。
- 実行する側はこの会話を知らないので、前提（どこまで終わっているか）も依頼に書く。
- 結果は `STATUS:` 行が現れるまで待つ。
