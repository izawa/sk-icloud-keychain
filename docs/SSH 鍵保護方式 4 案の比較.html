SSH 鍵の保護方式 4 案の比較 — Touch ID で、どの Mac からも、同じ鍵で

要件は「認証は Mac 内蔵の指紋センサー」「手持ちの全 Mac で同じ鍵」「1Password への新規依存を作らない」「1 台のハードウェアの故障に賭けない」の 4 つ。 鍵をハードウェアに閉じ込める案は「全 Mac で同じ鍵」と原理的に両立しないため、鍵を同期する側の設計で、依存先を Apple ID と自作コードだけに絞ったのが今回の案。

採用した案は 公証済みの DMG でダウンロードできます（README）。

結論：iCloud Keychain + 自作 sk-api provider を選ぶ

4 つの要件をすべて満たすのはこの案だけ。

  • ●Mac 内蔵の指紋で認証できる（YubiKey 方式を外す理由）
  • ●全 Mac で同じ鍵が使える（Secure Enclave 方式を外す理由）
  • ●1Password への新しい依存を作らない（1Password 方式を外す理由）
  • ●1 台のハードウェアが単一障害点にならない

依存先は Apple ID と自作コードだけに絞られ、サーバ側は既存の YubiKey と同じ sk 鍵として扱えるため、YubiKey Bio をそのまま予備として並走させられる。

受け入れるトレードオフ：鍵はハードウェアに拘束されず、生体認証ゲートはソフトウェアが担う。これは 1Password SSH agent と同じ保護モデルであり、「鍵が同期される」ことと表裏一体なので回避はできない。加えて、小さな dylib を自分で保守する責任を負う。
