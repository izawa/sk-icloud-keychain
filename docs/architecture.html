sk-icloud-keychain 構成図

SSH の秘密鍵は普段の Apple Account の iCloud キーチェーンで全 Mac に同期し、使うときの本人確認（Touch ID）は各 Mac の helper app がかけます。 Apple Developer Program に加入した開発用 Apple Account は、その helper app に署名するためだけに使います。

開発用 Mac：鍵の作成・署名・-K・sshd へのログイン（verify-required）まで確認済み インストール先：/Applications（dylib は app に同梱） MacBook Pro：インストール・両方向の同期・署名まで確認済み テスト VM（OpenSSH 9.6p1）：2 台から同じ鍵でログイン確認済み 本番用の鍵 ssh:icloud：本番サーバに 2 台からログイン確認済み（お試し用 Host）

2 台の Mac で共有されるもの SYNC

普段の Apple Account

Mac と iPhone で使っているアカウント。iCloud キーチェーンで秘密鍵を同期する役目だけを担う。

開発用 Apple Account（Developer Program）

Xcode にサインインして helper app に署名する役目だけを担う。iCloud の同期には関わらない。

iCloud キーチェーンで同期普段の Apple Account・E2E 暗号化

  • ed25519 の秘密鍵（32 バイト）
  • メタデータ：application、user、公開鍵、flags、作成日時。list と ssh-keygen -K はこれだけを読み、秘密鍵には触れない
  • 読めるのは access group FJYY683YHH.org.izawa.sk-icloud-keychain に属する app、つまり同じ Team で署名した helper だけ

Dropbox で同期iCloud ではなく、~/.ssh が Dropbox 上にあるため

  • 鍵ファイル ~/.ssh/id_ed25519_sk…。中身は key handle（skick1:<UUID>）と公開鍵だけで、秘密情報はない
  • ~/.ssh/config。provider のパスは /Applications/sk-icloud-keychain.app/Contents/Frameworks/libsk-icloud-keychain.dylib で、どの Mac でも同じ
  • Dropbox がなくても、鍵ファイルは ssh-keygen -K で作り直せる

Mac ごとに別々同期されない

  • 指紋と Touch ID の判定（各 Mac の Secure Enclave）
  • 署名用の証明書・秘密鍵とプロファイル（各 Mac の Xcode とログインキーチェーン。プロファイルは端末に紐づく）
  • helper app 本体（各 Mac でビルドする。コピーしても他の Mac では起動しない）

ログイン時の流れ SEQUENCE

  1. ssh がサーバに接続し、鍵での署名を求められるssh
  2. ssh-sk-helper が provider dylib を読み込み、sk_sign を呼ぶssh-sk-helper
  3. dylib が helper app を新しいパイプで起動し、application・key handle・署名対象を渡すdylib → helper
  4. helper が key handle の鍵を探し、登録時の application と一致するか確かめるhelper
  5. Touch ID で本人確認する（生体認証のみ、パスワードでの代替なし）helper・LAContext
  6. iCloud キーチェーンから秘密鍵を取り出し、SHA256(application) ‖ flags ‖ counter ‖ SHA256(data) に署名するhelper・Keychain
  7. flags に UP と UV、counter に Unix 時刻を入れて返し、sshd が verify-required で検証するdylib → ssh → sshd

安全性の立脚点 TRUST

秘密鍵を誰が読めるか

iCloud キーチェーンの E2E 暗号化と access group。読めるのは同じ Team で署名した helper だけ。

本人確認

helper の LAContext（ソフトウェアでかけるゲート）。Secure Enclave が鍵の使用そのものを強制するわけではない。

helper が本物か

Apple Development の署名とプロファイル。改変すると署名が壊れ、access group を使えなくなる。
